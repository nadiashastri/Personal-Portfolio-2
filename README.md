# Nadia Shastri — The Quad

My personal portfolio as a small 3D exploration game: a stylised recreation of the University of
Illinois Main Quad. Walk around in first person and discover who I am at real campus landmarks.

**Live site:** https://personal-portfolio-2-orcin.vercel.app/ · **Repository:** https://github.com/nadiashastri/Personal-Portfolio-2

## The interactive features

| Where | What happens |
| --- | --- |
| **Center Quad** | Walk up to the *About Me* sign and press **E**: a profile card types out my introduction, then shows my toolkit and contact links. |
| **Foellinger Auditorium** | Press **E** at the entrance to fade into a stylised auditorium and browse my projects on the big screen (← / →, wraps around). |
| **Illini Union** | A mini *Quad Day*: four student-organization booths and a work-experience noticeboard, each opening its own card. |
| **Guide (G)** | *Quick Travel* fast-travels you to any of the three stops. |
| **Compass** | The top-left compass tracks the direction you face and names the area you're in. |

Controls: **WASD / arrows** walk · **mouse** look · **Shift** jog · **E** interact · **G** guide · **Esc** pause/close.

## Tech stack

React 19 + TypeScript + Vite · Three.js via React Three Fiber and drei · Tailwind CSS · Motion ·
Vitest + React Testing Library · GitHub Actions (CI) · Vercel (automatic deployment from `main`). Architectural ornaments (column capitals,
balustrades, lamps, the domes, the 3D title lettering) are generated by a Blender Python script.

## Setup

Requires Node.js 22 or newer (CI uses 24).

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build locally
```

Review shortcuts (skip the intro): `?view=<name>` opens a named camera, e.g. `?view=aboutMe`,
`?view=quadDay`, `?view=foellingerEntrance` (full list in `src/config/viewpoints.ts`);
`?scene=auditorium` opens the project showcase; `?stats` shows an FPS meter.

## Tests

```bash
npm test           # run the whole suite once
npm run test:watch # re-run on save
npm run typecheck  # TypeScript checks
```

The suite (Vitest + React Testing Library, ~100 tests) covers the interactive features end to end,
both normal use and edge cases. For example:

- **About Me:** opens only within range; **E** out of range does nothing; repeated **E** never
  opens a second card; any key skips the typing; Escape vs. close button restore the mouse differently;
  contact links have the right targets and `noopener` on external links.
- **Project showcase:** next/previous, wrapping from the last project to the first, returning to the
  Quad out of range so it doesn't reopen, and *no* link buttons for missing or unsafe URLs.
- **Quad Day:** the correct organization opens; switching booths shows no stale content; only one
  popup can ever be open; the nearest booth wins when two are in range.
- **Quick Travel:** each destination teleports to a safe, reachable spot outside every obstacle and
  facing its target; a second trip during a transition is ignored; unknown destinations are rejected.
- **World layout:** the player spawns on a sidewalk, no tree or prop sits on a path, sidewalks keep
  realistic widths, Foellinger's forecourt keeps its projection, location labels don't flicker.

The 3D canvas itself needs WebGL, which the test environment doesn't have, so component tests
substitute a small stand-in for the scene and drive it through the same callbacks the real scene uses.

## CI/CD and deployment

**Continuous integration — GitHub Actions** (`.github/workflows/ci.yml`). The job
**"Quality checks, tests & build"** runs on every pull request and on every push to `main`:
`npm ci`, type-check, the full test suite, and a production build.

**Merge gate.** `main` is protected by a branch rule that requires a pull request and requires
"Quality checks, tests & build" to pass before merging, so failing changes can't reach `main`.

**Continuous deployment — Vercel.** The repository is connected to Vercel through its GitHub
integration. Every push to `main` (i.e. every merged, verified PR) triggers an automatic production
deployment, so the live site always reflects the latest `main` commit. Pull requests also get
Vercel preview deployments. Build settings live in `vercel.json` (Vite, `npm run build`, output `dist/`).

### Workflow

```bash
git checkout -b my-change        # work on a branch
# …edit, then check locally:
npm run typecheck && npm test && npm run build
git commit -am "Describe the change"
git push -u origin my-change     # open a pull request on GitHub
```

The PR's checks must pass before it can merge. Merging into `main` re-runs the checks on the merged
code, and Vercel deploys it to the live site automatically.

### Setting it up from scratch

1. **Vercel:** on vercel.com, choose *Add New → Project*, import this GitHub repository (the Vite preset
   is detected), and deploy. Production deploys from `main` are then automatic.
2. **Branch protection:** in GitHub, go to *Settings → Branches → Add rule* for `main`. Require a pull
   request before merging, and require the status check **"Quality checks, tests & build"**.

## Security

The site is fully static: there is no server, database, login, form or user-generated content, so
there is no data to leak and no server to attack. What remains is hardened as follows.

- **HTTP security headers** (set for every response in `vercel.json`, and checked by
  `src/__tests__/securityHeaders.test.ts`):
  - A strict **Content Security Policy**. Scripts load only from this site, with no inline scripts
    and no `eval`; `'wasm-unsafe-eval'` allows only WebAssembly, used by the 3D model decoder. Styles
    and fonts come only from this site and Google Fonts. The page can't be framed and has no plugins,
    forms or `<base>` overrides.
  - **Other headers:** `Strict-Transport-Security` (HTTPS only), `X-Frame-Options: DENY`
    (clickjacking), `X-Content-Type-Options: nosniff`, a `Referrer-Policy`,
    `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy`, and a `Permissions-Policy` that
    disables the camera, microphone, location, payments and similar features.
  - **Verified locally:** `npm run preview` serves the build with the same headers, so the policy is
    checked against the real site. It produced no violations in Chrome.
- **No injection paths:** content is rendered only as text, never as HTML, and there is no
  `innerHTML`, `eval` or `dangerouslySetInnerHTML`.
- **URL parameters:** the review shortcuts (`?view=`, `?scene=`, `?stats`) are only compared against
  fixed allow-lists, so a crafted value is simply ignored. Built-in object keys such as
  `?view=__proto__` are rejected too, which a test covers.
- **Links:** external links open with `rel="noopener noreferrer"`. Project and contact links render
  only if they're valid `https:` (or `mailto:`) URLs, so values like `javascript:` can never become
  links.
- **Failure handling:** if WebGL is unavailable or the 3D scene crashes, an error boundary shows a
  clear message instead of a blank page, and the rest of the UI keeps working.
- **Supply chain and CI:**
  - Every PR runs `npm audit` and fails on high-severity vulnerabilities in runtime dependencies.
  - The workflow runs with read-only permissions, and the repository holds no secrets.
  - `main` only accepts reviewed pull requests whose checks pass.

**Recommended repository settings:** under *Settings → Code security*, enable Dependabot alerts,
secret scanning and push protection. In the `main` branch rule, also block force pushes and
deletions.

## Project structure

- `src/content/` — all personal content (about me, projects, organizations, work, contact links).
- `src/config/` — the map: paths, building sites, interaction zones, fast-travel destinations.
- `src/scene/` — the 3D world: architecture kit, vegetation, ground, lighting, interactive installations.
- `src/ui/` — overlays: title screen, cards, project showcase, guide, compass.
- `blender/build_assets.py` — generates `public/models/*.glb` headlessly (`npm run assets`, needs
  Blender in `/Applications`). The models are committed, so CI and deploys don't need Blender.

## Known limitations

- **Desktop-first:** walking needs a keyboard and mouse. Phones and tablets can view the scene and
  the cards but have no touch controls yet.
- **Not every building is interactive:** only Foellinger's auditorium can be "entered", as a fixed
  view rather than a walkable interior.
- **Approximate architecture:** the buildings follow reference photos but are simplified and scaled to
  about 70% of the real Quad. The side halls stand in for real buildings without exact detail.
- **Performance:** the scene targets desktop GPUs, with fewer grass blades and a smaller shadow map on
  touch devices. The first load downloads about 1.5 MB of JavaScript (gzipped about 0.45 MB) plus
  about 3 MB of models.
- **Testing:** the 3D rendering and the feel of movement were checked visually and with screenshots,
  not by automated tests.
- **Fonts:** fonts load from Google Fonts at runtime.
